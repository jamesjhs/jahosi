UnityQA policy, use policy and disclaimer

How UnityQA works, what it can and cannot do, how information is handled, and what users should check before relying on any answer.

Status of this policy

Version: 1.0.0. Published: 11 October 2026. Last updated: 11 October 2026. Sources reviewed: 11 October 2026.

This policy is written for UnityQA at https://jahosi.co.uk/unityQA/. It will be updated over time as Unity releases, the source list, and the hosting or AI setup change.

This page is not legal advice. It is a practical public statement of how the UnityQA page is intended to work and the limits users should understand before using it.

Plain-English summary

  • UnityQA is an experimental AI-assisted information page for Unity Engine workflows. It is not a substitute for Unity documentation, release notes, professional training or project testing.
  • Use it as a guide to compare workflows, find official resources and ask better questions.
  • Do not treat any answer as the only valid workflow. Many Unity tasks can be solved through more than one route.
  • Always check the official Unity Manual, Scripting API, package documentation, release notes or Unity Support pages before relying on an answer.
  • Do not enter sensitive personal, financial, account, license, client, repository or unreleased project details into the chat.
  • UnityQA is instructed to stay within the validated Unity source list and to refuse unsupported speculation, unofficial package claims and version-mismatched advice.

What UnityQA is

UnityQA is a plain-English Q&A page for Unity Engine users. It is designed to help learners and makers understand common topics such as the Editor, GameObjects, Components, Prefabs, scripting, rendering pipelines, physics, animation, UI, navigation, assets, profiling, multiplayer and troubleshooting.

Design philosophy

UnityQA is built around source discipline, practical explanation and official signposting. It should help users decide what to try next, compare valid Unity workflows and know when to open the original documentation.

Functional overview

  • The chat sends the user's question and recent temporary browser-session chat history to the UnityQA server.
  • The server passes the question to a configured AI service with instructions to use only the validated Unity source list.
  • The page includes starter prompts, common questions, topic lookup by Unity area, display controls and browser-side PDF export.
  • The topic lookup sends a Unity subject to the UnityQA server, which returns official Unity documentation, learning, release and support resources.
  • After a successful topic lookup, limited official resource context may be sent with later chat questions so answers can point to the relevant Unity docs.
  • Cloudflare Turnstile may be used to reduce automated abuse before chat is enabled.

Use policy and disclaimer

Use UnityQA of your own accord

By using UnityQA, you choose to ask questions of your own accord. You remain responsible for deciding whether to act, what to check, and whether to cross-check the answer against official Unity sources. The page cannot know your project goals, package versions, platform target, license position, repository state, hardware, build pipeline or production constraints.

Not a substitute for the manual

UnityQA does not replace the Unity Manual, Scripting API, package documentation, release notes, Unity Learn, Unity Support or Unity Hub documentation. If an answer conflicts with official Unity documentation, the official source wins.

Workflow comparison

Many Unity tasks can be done several ways. UnityQA should explain alternatives where appropriate, for example Prefabs versus scene-only objects, MonoBehaviours versus package systems, URP versus HDRP, physics-driven movement versus scripted movement, UI Toolkit versus uGUI, or built-in services versus a custom backend.

Limitation of advice

Do not rely on UnityQA alone for production-critical decisions. A short answer can miss context such as platform requirements, render pipeline, package versions, memory budgets, multiplayer architecture, accessibility requirements or certification rules. Check the documentation and test in a copy of your own project before committing to a workflow.

Safety and support

UnityQA is not an emergency service and is not intended for crisis situations. For account, license, payment or billing issues, use Unity Support. For platform-holder SDKs, third-party assets, hardware or drivers, verify the relevant official vendor documentation.

Privacy policy

Data controller and contact

The data controller for UnityQA is James Rowson. For privacy questions, correction requests or communication preferences, use the Jahosi contact page.

Data you should not provide

Do not enter passwords, API keys, license details, account details, payment details, client files, private repository links, unreleased project data or any other sensitive information into the chat.

Information processed when using the page

  • Chat question: the text you submit is sent to the UnityQA server and then to the configured AI service so an answer can be generated.
  • Recent chat history: recent messages are held in your browser session storage and sent with later questions to preserve short-term context.
  • Topic lookup context: after a successful topic lookup, the page may send returned official Unity resource links with later chat questions.
  • Session token: a temporary browser-session token may be stored in session storage after Turnstile verification.
  • Display settings: high-contrast and large-font preferences may be stored in browser local storage.
  • PDF export: exports are generated in your browser from the conversation visible in that browser session.
  • Security and service data: standard web request metadata may be processed by the server, hosting provider, rate limiter or security tools.

Purpose of processing

Information is processed to provide the Q&A function, preserve temporary context in the user's browser session, generate topic signposting, reduce abuse, troubleshoot the service and improve safe operation. UnityQA is not designed to build profiles, target advertising or sell user data.

Storage and retention

UnityQA does not maintain a user account or permanent chat database for this page. Chat history is stored in browser session storage on the user's device for the current browser session. Display preferences are stored in local storage until cleared by the user.

Sources and freshness

UnityQA is constrained to a curated source list of official Unity sources and officially recognised Unity learning/support routes, including Unity Documentation, the User Manual, Scripting API, Unity Engine product pages, release support, Unity Hub, Unity Learn and Unity Support. The source list was last reviewed on 11 October 2026. Sources can change without notice.

Where UnityQA cannot answer from the validated source list, it should say so and signpost the relevant official Unity or vendor source instead of inventing an answer.

Workflow and safety review

User perspective

  • The main risk is over-reliance: users may treat a clear AI answer as the only correct Unity workflow.
  • The page repeatedly tells users not to enter sensitive personal, account or project information.
  • The tool should remain careful, plain and source-linked, especially for version-specific behaviour, APIs, package documentation, platform support and production decisions.

QA inspector perspective

  • The server-side prompt constrains answers to a validated Unity source list and requires references.
  • The server-side prompt explicitly requires refusals and warnings when the answer would depend on unsupported versions, unofficial sources, third-party packages or vendor-specific behaviour.
  • The topic lookup is a narrow signposting function, not a knowledge base or community forum replacement.
  • PDF export is user-initiated and browser-side, but users should avoid exporting sensitive content.
