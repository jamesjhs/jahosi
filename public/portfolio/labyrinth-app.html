LabyrinthApp

Native Android game foundation · Kotlin · Jetpack Compose · offline-first · version 0.1.1

LabyrinthApp is the dedicated Android repository for turning the existing Jahosi Labyrinth browser game into a proper native mobile game. It is deliberately not a WebView wrapper. The goal is an offline Kotlin app with native rendering, Android lifecycle resilience, local score persistence, touch-first controls, haptics, audio, accessibility settings, and Play Store-ready release discipline.

The current repository is at foundation stage: a launchable Android skeleton with Compose, a temporary neon/dark launch screen, clean permissions, debug and release build types, and a roadmap that keeps the later gameplay port honest about testing, performance, and device behaviour.

Idea / Need Identification

The browser version proved the game loop: procedural mazes, first-person movement, hints, lives, timers, high scores, and touch controls can fit inside a compact self-contained experience. The need for LabyrinthApp is different: mobile players expect native performance, reliable lifecycle handling, device-friendly controls, accessible settings, haptics, sound, and an app that keeps working without a server or browser cache assumptions.

The repository also answers a product risk early. A quick HTML shell would be easy, but it would carry the browser game's constraints into a place where Android can do better. LabyrinthApp therefore treats the port as a real Android game project from the start.

Development Aims And Stages

Parity

Port maze generation, pathfinding, practice, timed run, high score, hints, lives, minimap, level preview, and score tables into testable Kotlin systems.

Native Feel

Use Android rendering, Compose overlays, touch controls, audio, haptics, and performance controls to make the game feel intentionally mobile.

Release Discipline

Keep privacy, permissions, Play target SDK, versioning, accessibility, asset licensing, and real-device QA visible through every phase.

  1. 1. Native skeleton: launchable Kotlin/Compose app, temporary icons, no unnecessary permissions, and a clear placeholder screen.
  2. 2. Core game logic: deterministic maze generation, shortest-path hints, scoring, timers, modes, and replayable seeds.
  3. 3. Persistence and lifecycle: DataStore or Room-backed progress, local scores, settings, and run recovery across pause, restart, and rotation.
  4. 4. Native rendering and playability: maze drawing, movement, camera, collision, touch and external input, HUD, minimap, and overlays.
  5. 5. Polish and release: textures, audio, haptics, accessibility, diagnostics, performance profiling, monetization decision, and Play-ready release notes.

Project Progress

Current status is Phase 1, version 0.1.1. The Android skeleton builds as a native app with package com.jahosi.labyrinth, compile and target SDK 36, minimum SDK 26, and a clean no-permissions baseline. A startup crash found during real-device testing was fixed before the skeleton was described as stable.

Gameplay itself is not claimed yet. That is a strength of the repository rather than a gap in the story: it has a staged path from proof-of-concept web game to a native Android release candidate, with tests and exit criteria attached to each phase.
