BlanderQA

Blender 4.0 tutorial Q&A · official-source guided · Node/Express + static UI + constrained AI workflow

BlanderQA exists because Blender has a lot of powerful features that can feel fragmented when you are learning them in the middle of a project. The project is not trying to replace the manual. It is a careful translation layer: a way to turn complicated interface paths, modifiers, nodes, rendering choices, animation tasks, and Python basics into clearer questions and next steps.

The design philosophy is deliberately restrained. BlanderQA does not try to be a shortcut generator, unofficial tutorial dump, or version-agnostic guesser. Its job is narrower and more useful: help someone ask a better question, understand the likely Blender 4.0 route, and know which official source they should check next.

Core interaction

  1. 1. Pick a starter or ask a clear workflow question
  2. 2. Keep private project details out of the prompt
  3. 3. Follow the highlighted chat panel as the answer appears
  4. 4. Check the official source or local body before acting

Who it is for

The target audience is Blender 4.0 users who know what they want to make but are unsure which official workflow to follow: hobbyist 3D artists, illustrators moving into 3D, animators, technical artists, students, add-on experimenters, and people troubleshooting a project file. It is especially useful when a user needs to choose between several valid routes, such as direct mesh edits, modifiers, Geometry Nodes, shader changes, render settings, constraints, drivers, shape keys or Python automation.

What it can do

  • Explain Blender 4.0 concepts in plainer English without replacing the official manual.
  • Help compare direct modeling, modifiers, Geometry Nodes and sculpting routes.
  • Suggest practical next questions about materials, EEVEE, Cycles, compositing, animation, rigging and troubleshooting.
  • Point users towards official Blender 4.0 manual pages, release notes, support pages and API documentation.
  • Offer starter prompts, common questions and question packs for modeling, shading, rendering, animation, troubleshooting and add-on development.
  • Find official Blender resources by topic, with fallback links for broad or ambiguous topics.
  • Move users back to the chat panel when a starter or common question is used, with visible status, answer highlighting and a return-to-chat control.
  • Export the chat as a PDF for offline review or to take into a conversation.

Design philosophy

Calm before clever

The page avoids novelty UI and makes the first useful action obvious. The tone is steady because Blender learning often happens while a project is already half built.

Sources over confidence

The assistant is constrained to official Blender sources. The user is nudged back to the original manual, release notes and API pages before relying on a workflow.

Comparative, not absolute

Answers should explain the route and compare trade-offs. They should not pretend that one workflow is always correct when Blender supports several approaches.

Accessible by default

Large-font and high-contrast controls, collapsible panels, mobile-first spacing, and concise prompts make the page usable while someone is switching between browser and Blender.

Build and functions

BlanderQA is served from the same Node/Express portfolio application as the rest of Jahosi. The page itself is intentionally simple: static HTML, CSS, and browser JavaScript, with the server providing chat, topic lookup support, Turnstile-aware session handling, rate limiting, source-constrained prompt construction, and official Blender resource context after a successful topic lookup.

Limitations and guardrails

  • It is explanation and navigation support, not a replacement for the Blender manual, project testing or professional production review.
  • It is intentionally focused on Blender 4.0; later Blender 4.x releases may behave differently.
  • It should not be used to share sensitive personal, client, account, unreleased asset or confidential studio details.
  • It does not recommend third-party assets, paid add-ons, unofficial tutorials or unsupported scripts as authoritative sources.
  • AI responses can be incomplete or phrase something too strongly, so original Blender sources and test files must be checked before acting.
  • Context matters: scene scale, topology, render engine, color management, add-ons, hardware, file state and artistic intent can change the practical answer.

Why this belongs in the Jahosi portfolio
