Blender5QA

Blender 5.0 tutorial Q&A · official-source guided · Node/Express + static UI + constrained AI workflow

Blender5QA extends the BlanderQA idea to Blender 5.0. It is built for learners who are trying to make sense of a real Blender task while the application, the manual, and the available workflow choices all feel a little too broad at once.

The problem it solves is not simply "answer a Blender question". It helps turn short, search-style prompts into clearer learning routes: what official topic to check, which workflow family might fit, and where version-sensitive claims need to be treated carefully.

Core interaction

  1. 1. Ask a Blender 5.0 workflow or learning question
  2. 2. Search official resources by topic when needed
  3. 3. Compare likely approaches instead of receiving one brittle answer
  4. 4. Check the cited Blender source before relying on the result

Focus

Ask, compare, verify

Guardrail

Official Blender 5.0 manual, release, support and API sources.

What it does

  • Explains Blender 5.0 concepts in plain English while pointing back to official sources.
  • Helps users compare direct modelling, modifiers, Geometry Nodes, sculpting and Python/API routes.
  • Supports topic lookup for modelling, shading, rendering, animation, rigging, troubleshooting and add-on development.
  • Keeps OpenAI calls server-side and passes only bounded chat context from the browser.
  • Includes local session history, display preferences, official resource links, policy pages and privacy warnings.

Technologies implemented

Blender5QA lives inside the Jahosi Node/Express portfolio server. The front end is a static HTML/CSS/JavaScript page, while the server owns chat routing, resource lookup, rate limiting, Turnstile-aware session handling, prompt construction and the official Blender source list.

Why it belongs here

Like BlanderQA, this project is a practical information tool rather than a generic chatbot. The useful part is the structure around the model: source discipline, version focus, accessible controls, starter prompts, official resource lookup and a clear reminder that production workflows should be tested in the user's own file.
